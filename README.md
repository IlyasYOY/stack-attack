# Stack Attack

Первый играбельный прототип собственной 2D-аркады на **Godot 4.6.3 + GDScript** для Android и Web. Падающие ящики, движение и прыжок, толкание, очистка нижнего ряда, растущий темп, оба условия поражения, меню, локальные рекорды, настройки и собственная пиксельная и звуковая подача.

Илья подтвердил работу технической основы на телефоне. Сам игровой прототип, художественная подача и баланс ждут его проверки; новый PR не мержится без одобрения.

## Запуск и проверки

В каждом новом cloud shell сначала активировать закреплённый инструментарий:

```bash
source /workspace/setup-stack/env.sh
cd /workspace/stack-attack
bash scripts/check.sh
```

При доступном графическом дисплее: `godot --path .`. Без DISPLAY доступны headless-проверки и браузерная Web-версия.

Меню целиком помещаются на экране без прокрутки. Название и пункты расположены без общей панели поверх отдельной игровой демонстрации: простой AI использует обычную симуляцию, прыгает, двигает ящики, очищает ряды и перезапускает проигранные партии. Демонстрация не изменяет личную игру и рекорды. В настройках слышны её музыка и эффекты; отдельной кнопки проверки звука нет. На экране результата счёт центрирован, длинное число помещается в одну строку; Все обычные кнопки меню, результата и паузы, включая Android-переключатель вибрации, используют единый стиль конца игры: небольшую тёмную полупрозрачную подложку и тонкую границу. Состояния normal/hover/pressed/focus заданы общей темой; размер touch-областей сохранён.

Клавиатура: ← → для движения, пробел для прыжка, Escape для паузы/продолжения. На Android и Web доступны touch-кнопки с одновременным движением и прыжком. В портрете кнопки снизу, в альбоме — по бокам; поворот сохраняет состояние партии.

## Android и Web

```bash
source /workspace/setup-stack/env.sh
python3 scripts/create_debug_key.py /workspace/stack-attack-local/debug-signing
source /workspace/stack-attack-local/debug-signing/debug-signing.env
bash scripts/export.sh all
python3 scripts/check_web.py
```

Результат — `build/android/stack-attack-prototype-debug.apk` и `build/web/`. Отдельно: `bash scripts/export.sh web` или `bash scripts/export.sh android`. Web открывать через HTTP:

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory build/web
```

Адрес: `http://127.0.0.1:8765`, не `file://`. Требуется WebGL 2. Chromium/Playwright уже есть в опубликованном окружении; тест включает браузерные сценарии, сохранение после reload и проверку фактического звукового сигнала.

Android: API 24+, ARM64; `org.ilyasyoy.stackattack.techtest`, versionCode 10, `0.2.8-prototype`. APK подписан тестовым ключом. Установка из выбранного источника должна быть разрешена на телефоне. CI использует новый временный ключ на каждый run, поэтому может понадобиться удалить предыдущий тест перед установкой с другой подписью; это удаляет его локальные данные. Локальный ключ сохранять отдельно вне Git, если нужны совместимые тестовые обновления. Финальная публикация и release-подпись — отдельное решение.

## Приватные сборки

GitHub Actions проверяет импорт, тесты и headless-запуск. На PR и main дополнительно экспортирует Android/Web и сохраняет приватный Actions artifact на 14 дней. Скачать его можно на странице завершённого run после входа в GitHub с доступом к репозиторию. Внутри APK, Web ZIP, точный commit, SHA-256 и публичные отчёты подписи/метаданных. Ключи и credentials туда не входят. Публичный hosting и GitHub Release не создаются.

После коммита и локальных проверок `python3 scripts/package_builds.py` упаковывает подтверждённые сборки в `build/deliverables/`, сверяя commit и контрольные суммы с записями экспорта и браузерного теста.
