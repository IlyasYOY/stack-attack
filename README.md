# Stack Attack

Рабочее название собственного 2D-аркадного проекта для Android и Web на Godot 4 + GDScript.

## Состояние

Первая техническая основа: **Godot 4.6.3 stable + GDScript**, Compatibility, Android и Web. Минимальная сцена показывает статус запуска, ориентацию и счётчик нажатий. Это технический тест без игровых механик; изображения и компоновка не утверждают будущий художественный стиль.

Облачные headless-проверки, Web и APK проверяются командами ниже. Запуск APK на реальном телефоне остаётся отдельной проверкой Ильи.

## Запуск и проверка в опубликованном облачном окружении

В **каждом новом shell** сначала активировать инструменты:

```bash
source /workspace/setup-stack/env.sh
cd /workspace/stack-attack
bash scripts/check.sh
```

Для графического запуска при наличии дисплея: `godot --path .`. В обычном shell облачной задачи DISPLAY может отсутствовать; это не мешает headless-сборкам и проверке Web в Chromium.

## Обе тестовые сборки

Один раз создать отдельный тестовый ключ **вне checkout**, затем сохранять его вместе с приватным env-файлом для следующих тестовых обновлений:

```bash
source /workspace/setup-stack/env.sh
python3 scripts/create_debug_key.py /workspace/stack-attack-local/debug-signing
source /workspace/stack-attack-local/debug-signing/debug-signing.env
bash scripts/export.sh all
python3 scripts/check_web.py
```

Результат: `build/android/stack-attack-tech-debug.apk` и `build/web/index.html` с соседними файлами. `scripts/export.sh web` не требует ключа; `scripts/export.sh android` собирает только APK. Chromium и Python Playwright уже есть в опубликованном окружении.

Для ручной проверки Web:

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory build/web
```

Открыть `http://127.0.0.1:8765`, а не `file://`. На телефоне установить подписанный APK, нажать «Проверить ввод», повернуть телефон и проверить, что счётчик сохранился. Android package: `org.ilyasyoy.stackattack.techtest`, Android 7.0 / API 24+, ARM64. Для установки потребуется разрешение на установку из выбранного источника; Play Store, release-подпись и публикация сюда не входят.

Тестовый ключ не предназначен для релиза. Обновления поверх установленного теста требуют прежнего package и того же ключа; при потере ключа или смене подписи понадобится удалить прежний тест с потерей его локальных данных. Финальный игровой package и подпись будут отдельным решением. Никогда не коммитить ключ или приватный env-файл.

## Автоматизация и доставка

GitHub Actions запускает импорт, GDScript-тест и headless-запуск на PR, включая draft, и при push в main или codex/**. На PR и main дополнительно собираются Android/Web и сохраняются как **приватный Actions artifact** на 14 дней. Его можно скачать на странице завершённого run после входа в GitHub с доступом к репозиторию. Chromium-проверка выполняется локально; CI не выдаётся за проверку телефона.

В CI используется новый временный debug-ключ для каждого run, без постоянных secrets. Такой APK может потребовать удаления предыдущего теста перед установкой, если его подпись другая. Локальный ключ из команд выше сохраняется отдельно и позволяет выпускать совместимые локальные обновления. В Actions artifact входят только APK, Web ZIP, commit, SHA-256 и публичные результаты проверки подписи/метаданных; signing-файлы туда не входят. Это не GitHub Release и не публичная публикация.

После коммита и повторных проверок команда `python3 scripts/package_builds.py` создаёт APK, Web ZIP и манифест с точным commit и SHA-256 в `build/deliverables/`. Web ZIP нужно распаковать и обслуживать по HTTP. Сборки передаются через Library, без публичного hosting и релиза.
