# Первый играбельный прототип

Согласованные правила находятся в `docs/plan.md`. Илья подтвердил работу технического APK на телефоне и разрешил собрать весь первый этап одним новым PR. Приёмка самого игрового прототипа, художественной подачи и баланса ещё впереди. Это самостоятельная пиксельная игра с собственными спрайтами, музыкой и звуками, а не оставленная техническая сцена.

## Как играть

- Сдвигать ящики движением в их сторону; прыгать, чтобы оказаться сверху. Падающий ящик также можно сдвинуть при боковом контакте.
- Полностью заполненный нижний ряд исчезает независимо от цвета. Остальное содержимое склада и герой плавно опускаются вместе. Последующие полные нижние ряды очищаются цепочкой; множителя очков нет.
- Одна жизнь. Падающий на голову ящик завершает партию. Если хотя бы одна устойчивая башня достигает полной высоты поля, краны блокируются и партия заканчивается.
- Без опоры ящики падают. Сдвиг нижнего ящика из стопки опасен: верхний может упасть на героя. Разбивание ящиков не реализуется.
- За время очки не начисляются. Сбросы постепенно становятся чаще до предела; скорость героя не меняется. За один сброс выпускаются один или два ящика, в разные колонки.

Клавиатура: стрелки влево/вправо, пробел для прыжка, Escape для паузы/возврата. Экранные кнопки поддерживают одновременные движение и прыжок. В портрете они снизу, в альбоме — по бокам. Поле всегда 10×11 клеток; поворот меняет только представление и сбрасывает удержание touch-кнопок, сохраняя партию.

Главное меню: «Играть», «Рекорды», «Настройки». В партии — только счёт и пауза. Пауза: продолжить, начать заново, главное меню. После проигрыша — итоговый счёт, повтор и главное меню. Данные завершённой партии записываются ровно один раз; выход в меню во время паузы не добавляет рекорд.

## Параметры для проверки игрой

Параметры редактируются в ресурсе `game/prototype.tres` через Inspector. Начальные значения определены в `game/tuning.gd`.

| Параметр | Стартовое значение |
| --- | --- |
| Поле | 10 колонок × 11 рядов |
| Скорость героя | 3.6 клетки/с |
| Прыжок / гравитация героя | 8.8 клетки/с / 24 клетки/с² |
| Падение ящика | гравитация 17, предел 6 клеток/с |
| Толкание | 3.1 клетки/с, один ящик на клетку за перемещение |
| Первый сброс | через 3.5 с |
| Интервал | от 4.2 до 1.35 с, уменьшение на 0.018 с за секунду активной партии |
| Вероятность двойного сброса | 32% |
| Очки за ряд | 100, без множителей |
| Очистка / совместное опускание | 0.22 / 0.25 с |
| Рекорды | десять лучших результатов на устройстве |

В начале три ящика находятся на полу. Краны показывают колонки следующего сброса. Это выбранные стартовые параметры прототипа, а не окончательная настройка баланса. Физика — собственная AABB-симуляция с шагом 1/120 с, без вращения ящиков; накопитель сохраняет шаги независимо от частоты отрисовки. Во время очистки обычная физика и сбросы приостановлены, поэтому общее опускание не создаёт ложного удара по герою. Пауза и потеря фокуса останавливают партию.

## Визуальная и звуковая подача

Авторские пиксельные герой, ящики, ночной склад, лес, краны, фонари и эффекты очистки. Файлы в `art/`, генератор спрайтов — `scripts/generate_art.py` (Pillow нужен только для повторного создания ассетов). Исходная SVG-иконка также собственная. Материалы Stack Attack, Braid и Dead Cells не используются.

Музыка и эффекты созданы процедурно для проекта без сторонних записей; воспроизводимый генератор — `scripts/generate_audio.py`. Музыка — оригинальный 16-секундный цикл. PCM и потоковое воспроизведение используются на обеих платформах, с отдельными шинами Music и Effects. Звук запускается после пользовательского действия. Две громкости сохраняются независимо. Android-вибрация включается при прыжке, очистке ряда и проигрыше и отключается в настройках; в Web переключатель отсутствует. Принятие художественного результата и ощущения управления остаётся за Ильёй.

## Сохранение

`user://stack-attack-profile-v1.json`: громкость музыки, звуков, Android-вибрация и локальная десятка рекордов. Запись через временный файл с переименованием. Повреждённые данные не останавливают игру; значения проверяются и ограничиваются. Аккаунтов и синхронизации нет. В Web используется IndexedDB Godot; приватный режим, запрет хранения и очистка данных сайта могут удалить сохранение. Первое сохранение асинхронно синхронизируется с браузером, поэтому браузерный тест ждёт завершения записи перед перезагрузкой.

## Проверки и доставка

```bash
source /workspace/setup-stack/env.sh
bash scripts/check.sh
source /workspace/stack-attack-local/debug-signing/debug-signing.env
bash scripts/export.sh all
python3 scripts/check_web.py
```

Headless-набор проверяет движение, прыжок, толкание включая падение, потерю опоры, опасность ящика, очистки и цепочки, отсутствие ложной гибели, оба проигрыша, темп, постоянную скорость, локальные данные и экраны. Восемь воспроизводимых партий дополнительно проверяют границы и отсутствие проникновения ящиков. Сравниваются 30 и 144 FPS и длинный кадр. После независимого review добавлены восемь направленных сценариев диагонального и бокового контакта: обе стороны движения, исходное касание/небольшой вертикальный зазор и уже активный сдвиг на разной скорости. В каждом из 120 шагов каждого сценария проверяется отсутствие пересечения всех пар ящиков, без прежнего уменьшения проверяемых прямоугольников. Исходный случай воспроизведён в Godot до исправления; ограничение по горизонтали перепроверяется на текущей высоте каждый шаг, боковой удар прекращает команду сдвига, а вертикальная поддержка учитывает даже узкое реальное касание. Падение в стороне от препятствия и толкание в полёте сохранены.

Chromium проверяет настоящий экспорт через HTTP: мышь/клавиатура, одновременные touch-кнопки, портрет/альбом, паузу, возврат, оба перезапуска, выход в меню, цепочку, оба поражения, рекорды/настройки после reload, отсутствие браузерных ошибок и реальные ненулевые аудиосэмплы на каждой отдельной шине. Скриншоты и отчёт — `build/`. Подсказка меню использует слова «Стрелки» и «Пробел»: Unicode-стрелки отсутствуют в Web fallback-шрифте на узких экранах. Браузерная регрессия проверяет покрытие каждого символа меню фактическим шрифтом экспортированной игры; для длинных подсказок увеличена высота панели в портрете. В debug Web экспорт диагностический мост доступен только с `?qa=1`; воспроизводимые сценарии включаются только тестовым скриптом, не игровым интерфейсом. В release мост отключён. Обычный запуск без параметра — обычная партия со случайными сбросами.

CI выполняет headless-набор и обе сборки на точном head PR. Приватный Actions artifact содержит `stack-attack-prototype-debug.apk`, Web ZIP, commit, SHA-256 и результаты Android-проверок. Ключей в нём нет; срок хранения — 14 дней. Нужен вход в GitHub с доступом к репозиторию, публичный релиз не создаётся.

Android: API 24+, ARM64, package `org.ilyasyoy.stackattack.techtest`, versionCode 4, versionName `0.2.2-prototype`. Каждый CI run получает новый временный debug-ключ; для установки вместо предыдущего теста может понадобиться удалить старый APK с его локальными данными. Для совместимых локальных обновлений нужно сохранять отдельный локальный ключ вне Git.

Технический APK предыдущей части Илья уже проверил на телефоне. **Этот игровой прототип на телефоне ещё не проверен**. Отдельно остаются реальный Android touch/вибрация/звук, вырезы и системные панели, мобильные браузеры и производительность на устройствах. SwiftShader и эмуляция touch не заменяют эти проверки. Баланс и визуальную подачу проверяем по пробным партиям Ильи.
