# Before making the repository public

- [ ] Decide which history to publish. Review old commits, all branches, tags and PR refs, including the deleted line in the diff of the PR that introduced this checklist. Fixing the current tree preserves earlier versions. Options include publishing a separate clean snapshot or agreeing on how to clean the existing history. [GitHub instructions](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
- [ ] Review descriptions, comments, attachments and diffs for open and closed PRs. PRs #1–3 contain links to builds and logs that were considered private at the time. Also review issues, releases and Actions logs.
- [ ] Inspect the two Actions archives from commits `bd56a63` and `383cdce` while they are available, along with any newer artifacts. Check the nested Web ZIPs and APKs, signature reports, metadata and delivery files. Record which builds may be made public.
- [ ] Verify the actual Actions settings for workflow and `GITHUB_TOKEN` permissions, external fork PRs, manual approval, access to secrets, runners, branch protection and retention. Test behavior separately on an agreed external fork. Once the repository is public, Actions history and logs will be public, and signed-in users with read access will be able to download artifacts. [GitHub visibility rules](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility).
- [ ] Agree on publication of the two personal email addresses in commit metadata. The owner should check the addresses in Git. A new commit preserves the metadata of earlier commits.
- [ ] Decide on a license for the code and game assets, review distribution rights for the [eight project PNGs](assets.md), and check that builds intended for distribution contain the Godot notices.
